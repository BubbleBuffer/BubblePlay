# BubblePlay mark exports

The approved master is `bubbleplay-icon.svg`, the unified BubbleBuffer suite icon: the screen cat with an apricot cursor on an ivory tile, built to the Pawth icon standard (BubblePlay E1e, Android adaptive template). Regenerate the Android, Windows and web exports and the visual proof sheets with:

```powershell
python branding/build-icons.py
python branding/test_build_icons.py
```

Requires Python 3.10+, Pillow, and an installed Chrome/Chromium (or set `CHROME` to its path). `--no-preview` skips proof sheets. `--followups` regenerates the Windows exports only, without writing Android resources or web favicons. Chromium uses an isolated temporary profile and no sandbox for these trusted local render inputs.

## What is derived from the master

- `out/bubbleplay-tile.svg` and `worker/public/favicon.svg` are the master as it is (ivory tile, full bleed).
- `out/bubbleplay-tight.svg` is the master without its tile. `out/tray-32.bgra` is a premultiplied 32px raster of it; it is unused (the tray uses `out/bubbleplay-tray.ico`).
- `out/bubbleplay.ico` holds 16, 20, 24, 32, 48, 64 and 256px frames, each rendered from the master tile at its own size. `small/16.png`, `small/20.png` and `small/24.png` are exact copies of those ICO frames. The small frames keep the ivory field.
- `out/bubbleplay-tray.ico` is the notification-area icon: 16, 20, 24, 32, 40 and 48px frames rendered from the tight mark on a transparent background, cropped to a square around the mark so it fills each frame with a 1/16 margin per side (1px at 16px). `out/bubbleplay-tray-dark.ico` has the same frames for dark taskbars: the outer outline (monitor silhouette, neck and foot) is drawn in the tile colour instead of charcoal; the screen edge, face and cursor are unchanged.
- `worker/public/favicon-32.png` is the 32px tile frame.
- `android/.../drawable-xxxhdpi/ic_launcher_foreground.png` is the master on the 108dp adaptive canvas, 432px, with the mark where the master places it. `values/colors.xml` takes the tile colour as `launcher_background`, and `mipmap-anydpi/ic_launcher.xml` wires the layers together.

These rasters are regenerated by this script and replace the earlier Pawth exports. The difference is at anti-aliased edges only: a mean of 0.1 to 1.5 levels out of 255 for the foreground and the 16, 24, 32, 48, 64 and 256px frames, and about 6 levels at 20px.

## Not regenerated

- **Login brand mark:** the login page (`worker/public/login.html`) and its Go relay code (`relay/auth.go`) were deleted at the cutover. The script never touched them, and nothing here regenerates them.
- **Monochrome layer** (`android/.../drawable/ic_launcher_monochrome.xml`): still the old art. It is in a design round, so the script leaves the file as it is. The monochrome proof sheet is drawn from that file.

## Previews

`preview/android-launcher.png` shows the 66dp safe circle and circle/squircle masks on the adaptive canvas. `android-monochrome.png` shows the themed layer. `windows-ico.png` shows frames at actual size and enlarged on #F3F3F3 and #202020 taskbars. `windows-tray.png` shows both tray ICOs' frames the same way, each on both taskbar colours. `login-desktop.png` and `login-narrow.png` render the Worker login asset. `login-go-desktop.png` and `login-go-narrow.png` render the Go login template with synthetic nonce and approved-browser state. These use each login's CSP in a local preview server; they are visual fixtures, not a deployed authentication test.

Known gap: `test_build_icons.py` still asserts the previous hand-hinted 16/20/24 frames and the vector foreground, so it does not pass against these outputs until it is updated.

Windows executable resources are compiled by the installed Windows SDK `rc.exe` from `host/build.rs` (MSVC; override its path with `RC`). No Rust build dependency is needed. `out/bubbleplay.ico` is icon resource 1 (the exe and Start-menu icon) in both binaries; `out/bubbleplay-tray.ico` and `out/bubbleplay-tray-dark.ico` are icon resources 2 and 3 in the tray binary. The notification area loads one of them with `LoadImageW` at the system-DPI small-icon size: resource 3 when HKCU `Software\Microsoft\Windows\CurrentVersion\Themes\Personalize` `SystemUsesLightTheme` is 0 or missing, resource 2 otherwise. It re-reads the value on each tray tick and on `WM_SETTINGCHANGE` ("ImmersiveColorSet") and swaps the icon. Host and input-agent status stay in the existing tooltip and menu text.
