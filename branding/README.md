# BubblePlay mark exports

The approved master is `bubbleplay-icon.svg`, the unified BubbleBuffer suite icon: the screen cat with an apricot cursor on an ivory tile, built to the Pawth icon standard (BubblePlay E1e, Android adaptive template). Regenerate the Android, Windows and web exports and the visual proof sheets with:

```powershell
python branding/build-icons.py
python branding/test_build_icons.py
```

Requires Python 3.10+, Pillow, and an installed Chrome/Chromium (or set `CHROME` to its path). `--no-preview` skips proof sheets. `--followups` regenerates the Windows exports only, without writing Android resources or web favicons. Chromium uses an isolated temporary profile and no sandbox for these trusted local render inputs.

## What is derived from the master

- `out/bubbleplay-tile.svg` and `worker/public/favicon.svg` are the master as it is (ivory tile, full bleed).
- `out/bubbleplay-tight.svg` is the master without its tile. `out/tray-32.bgra` is a premultiplied 32px raster of it; it remains an unused alternative.
- `out/bubbleplay.ico` holds 16, 20, 24, 32, 48, 64 and 256px frames, each rendered from the master tile at its own size. `small/16.png`, `small/20.png` and `small/24.png` are exact copies of those ICO frames. The small frames keep the ivory field.
- `worker/public/favicon-32.png` is the 32px tile frame.
- `android/.../drawable-xxxhdpi/ic_launcher_foreground.png` is the master on the 108dp adaptive canvas, 432px, with the mark where the master places it. `values/colors.xml` takes the tile colour as `launcher_background`, and `mipmap-anydpi/ic_launcher.xml` wires the layers together.

These rasters are regenerated by this script and replace the earlier Pawth exports. The difference is at anti-aliased edges only: a mean of 0.1 to 1.5 levels out of 255 for the foreground and the 16, 24, 32, 48, 64 and 256px frames, and about 6 levels at 20px.

## Not regenerated

- **Login brand mark** (`worker/public/login.html`, `relay/auth.go`, between the BRAND-MARK markers): maintained separately. It still carries the old art and the script leaves it untouched.
- **Monochrome layer** (`android/.../drawable/ic_launcher_monochrome.xml`): still the old art. It is in a design round, so the script leaves the file as it is. The monochrome proof sheet is drawn from that file.

## Previews

`preview/android-launcher.png` shows the 66dp safe circle and circle/squircle masks on the adaptive canvas. `android-monochrome.png` shows the themed layer. `windows-ico.png` shows frames at actual size and enlarged on #F3F3F3 and #202020 taskbars. `login-desktop.png` and `login-narrow.png` render the Worker login asset. `login-go-desktop.png` and `login-go-narrow.png` render the Go login template with synthetic nonce and approved-browser state. These use each login's CSP in a local preview server; they are visual fixtures, not a deployed authentication test.

Known gap: `test_build_icons.py` still asserts the previous hand-hinted 16/20/24 frames and the vector foreground, so it does not pass against these outputs until it is updated.

Windows executable resources are compiled by the installed Windows SDK `rc.exe` from `host/build.rs` (MSVC; override its path with `RC`). No Rust build dependency is needed. The notification area loads resource 1 from that ICO with `LoadImageW` at the system-DPI small-icon size. Host and input-agent status stay in the existing tooltip and menu text.
