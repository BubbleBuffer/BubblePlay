This PC

  • A pinned section above Your PCs, not the first row. Hosting is a different job (this computer is the one being reached), so a seam separates it, it never gets a Connect button, and it cannot be sorted or scrolled away among remote PCs.
  • Selecting it widens the panel to two columns: settings left, devices and requests right. Build, roll back and logs sit in a quiet footer row.
  • Moss marks hosting; apricot stays reserved for connecting and Allow.
  • The tray stays the background presence and owns tray.json. The app never writes that file; it reads status and changes settings only through the tray's control interface: a per-user, per-session named pipe whose ACL allows only the signed-in user. The tray relays host status to the app.
  • Stop hosting stops the host but keeps the tray running; the tray then shows Stopped and can start hosting again. Quitting the tray is a separate action.
  • CPU mode is one on/off setting that takes effect after a host restart.
  • Approvals show in both the app and the tray, keyed by request ID. The first answer wins; the other place dismisses itself with "Answered on <device>" (the This PC: answered state).

Settled for this app

  • No site gate: the native viewer is exempt, like Android. The gate screen is browser only and is not in this app.
  • Key: %APPDATA%\BubblePlay\client\device.bpkey, DPAPI at rest; Export and Import live in Settings (gear in the list footer), next to Replace key.
  • A new PC opens in Work, the browser client's default.
  • Before sign-in: a fresh ntfy approval sent by the PC itself, nothing else.
  • Everything marked Draft (rotation copy and timings) is for owner review.

Layout

  • Custom 36 px title bar. Home: broad PC list with a Connect button on every row, plus a 400 px panel for the selected PC. The panel holds facts, not choices.
  • This device's own ID sits in the list footer, because pairing and vouching compare IDs.
  • A vouch request swaps the panel for a request panel with an attention seam; the PC row carries a "1 pairing request" status.
  • Flow screens: a 300 px near-black step rail and a 680 px max column, left-aligned.

Type scale

  • Panel name: Bricolage 36/0.95, wdth 86. Screen titles: Bricolage 28/1.05.
  • Row name 15/720, body 14/450, labels 12-13/720, Atkinson Hyperlegible Next.
  • Fragment Mono for device IDs (12-15), the comparison number (34-44, grouped 3+3), codes, timers.

Colour

  • Apricot: Connect / the one main action per screen, the selection marker, waiting pulses.
  • Attention #F0D29C: pairing requests. Danger #E5B1AA: refused key, PC key changed, Forget. Constructive #CAD8CD: Online and done steps.
  • Every status also has a word (Online, Offline, 1 pairing request).

Motion and egui cost

  • Hover 120 ms; screen change 180 ms fade plus 8 px slide; reduced motion snaps.
  • Countdown timers repaint once per second only.
  • Costly: the segmented code input and paste detection of a pairing link are custom widgets. The ring pulse needs a repaint every frame while visible; cap at 30 Hz.
