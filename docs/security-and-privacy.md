# Security and privacy

The public product is Windows desktop streaming, input, clipboard and file transfer. The private Node companion, command execution and its identity packages are excluded from the public Windows ZIP and public relay source. The optional Windows admin-input helper is a different, restricted component.

The Cloudflare path requires browser approval followed by application-password login. The Go path accepts an application password plus an authenticator code, or a password after ntfy approval; remembered browser approval can be reused. Go stores an Argon2id password hash, hashed browser tokens and persistent replay/revocation state. Native host registration and endpoints use separate credentials. Host relay addresses require TLS except for loopback development, and browser WebSocket upgrades enforce their own origin. Configuration files on Windows store host secrets using CurrentUser DPAPI.

In WebSocket mode, TLS protects the connection between each endpoint and the relay. The relay can see video, input, clipboard and file payloads above that TLS layer. This is not endpoint-to-endpoint encryption; self-host on trusted infrastructure. WebRTC media uses its own encrypted transport, while signaling still passes through the relay.

Clipboard and file access are sensitive by design. The host offers individual copied/selected files for download; the browser cannot browse an arbitrary host folder through that transfer feature. Remote input acts as the signed-in Windows user. Turning on the optional Admin mode extends input into elevated apps. Without the optional secure-desktop helper, UAC prompts and lock screens suspend input and capture while the viewer session stays connected; the viewer holds the last presented frame until normal-desktop capture recovers. Live transition and recovery timing remain unverified.

The optional SYSTEM secure helper views Winlogon only and hands frames to the user host for encoding. With Admin mode off, its only accepted action is targeted UAC deny; with Admin mode on it also accepts pointer, keyboard and Unicode text input, including lock-screen passwords. It rereads the console user's tray.json on each request and fails off when that policy is unreadable. Its pipe and read-only shared mapping are restricted to SYSTEM and that console user's SID; session/client checks, a version handshake and protected helper image verification apply. Clipboard/file paste is suspended on secure desktops. Logs contain state and deny metadata, never pixels or typed text. Live secure capture, protected input, consent cancellation and task installation are not yet qualified.

Residual risk: another process running as the same console user can connect to the helper and can change the user-writable Admin-mode setting. Installation does not establish an isolation boundary between those processes. An authorized viewer can see sensitive secure-desktop information; a WSS relay can also see that video and input above TLS. Turn Admin mode on only when protected input is needed. See [the secure-desktop contract and owner test](architecture/secure-desktop.md).

The first candidate uses unsigned Windows binaries and NVIDIA encoding. It contains no kernel mouse driver, automatic driver installation, lab helper or private companion.

For a bug report, include the app build, relay build, operating system, browser and a minimal redacted reproduction. Do not post credentials, cookies, identity files, raw desktop captures or unrelated user files. A dedicated private vulnerability-reporting channel remains to be selected before public launch.
