# Session UI

The receiver keeps quick actions beside the stream in a docked bar. The stream's layout and input coordinates account for that bar; controls do not cover the desktop during ordinary use.

The approved BubblePlay mark appears on launcher icons, login pages and the Windows notification area (with host/input status in its tooltip and menu), outside the session strip; About links to the relay operator's configured source code.

The host keeps the PC display on while a viewer is attached and attempts to wake an unavailable Default desktop with rate-limited local input. A recoverable join defers the existing Desktop unavailable state for at most two seconds, then announces it until verified capture sends active again. The pending first-frame request survives local capture recovery: its usual eight-second timeout extends to at most thirty seconds from the request, with up to eight seconds after recovery inside that bound. Browser and Android use their existing desktop-state messages.

## Browser

The existing connection status shows "This window needs Admin mode — turn it
on at the PC" for the `input-status` `ctl` kind with reason `admin-required`, and "Admin mode
helper isn't responding" for `"admin-unavailable"`. Android uses its existing
status line for the same warning. Controls stay enabled; explicit `reason:null`
clears the warning, while receipt-only messages preserve it. Host diagnostics
count input kinds, drop reasons, routes and injection results without logging
key codes, text or coordinates.

The browser opens its signaling socket immediately on startup, runs the phase-2 hello and `auth-*` handshake on it, and then sends the first-frame requests and the WebRTC offer as `ctl` kinds, with the existing five-second first-frame watchdog. Automatic no-RTP fallback waits at least five seconds from the latest first-frame request and the last startup progress, requires connected ICE and peer state, and checks that neither RTP nor a presented frame has arrived; a terminal RTC failure also selects WSS in automatic mode. A remembered fallback lives only in the current tab's sessionStorage, so a new tab session tries WebRTC again. Explicit transport choices and transient disconnections retain their existing policies. Each relay socket still checks current approval and login validity before admission.

Desktop pointers use a 32 px top strip. Touch pointers use a 48 px bottom bar plus its seam. Desktop actions include Monitors, Shortcuts, Files, Fullscreen and Settings; clipboard retry and zoom reset appear only when needed. Touch adds Keyboard, Touch mode, Keys, Arrows and More.

Popovers open with one action and close on an outside press or Escape. Only one is open at a time. Keyboard navigation moves between rows and restores focus on close; Escape used by a popover does not reach the remote PC. Mouse-opened controls preserve remote-input focus.

Desktop fullscreen hides the strip. Resting at the top edge reveals a handle that brings controls back temporarily; an open popover keeps them visible. Touch fullscreen keeps the bottom bar. Ctrl+wheel and touch pinch zoom the viewport; a reset chip appears while zoomed.

The Monitors popover marks the current monitor and exposes [Follow active window](follow-active-window.md) only for a capable host. Files appears only with `fileTransfer`; an offer or active transfer adds an indicator without opening the popover automatically. Desktop drops, paste and picker uploads have different [file-transfer behavior](file-transfer.md).

Settings opens a slide-over with stream quality, keyboard lock, scroll speed, pointer mode, default monitor, clipboard copying, browser access, diagnostics and version information. Browser support determines whether keyboard lock is available. Browser access offers Switch PC, Lock and Forget this browser. Lock forgets the unlocked device key in memory. Forget this browser clears the site-gate approval; it keeps the device key and the paired PCs.

Copy from the PC automatically defaults on. Turning it off keeps host clipboard updates behind the Copy remote clipboard chip until it is clicked. Ctrl/Cmd+V uses the local clipboard; local paste, copy or cut drops a pending host snapshot.

[`settings.js`](../../worker/public/settings.js) stores a versioned `bubbleplay.settings` record in localStorage. Settings apply live; default monitor is requested once per page session. Invalid records fall back to defaults and storage errors leave the session usable. [`chrome.js`](../../worker/public/chrome.js) owns popover focus, shortcuts and fullscreen reveal; [`receiver.js`](../../worker/public/receiver.js) connects those controls to the session. Relay version is shown when supplied by the relay; a host build is not currently carried on the wire.

## Android

The native app uses a docked bottom bar and popovers, with its own gesture and keyboard behavior. Settings opens inside the active stream activity so the stream stays in the foreground. Preferences cover server/login, background survival, touch, mouse and keyboard, display, codec, clipboard copying and diagnostics; codec changes reconnect the stream.

A hardware mouse follows the browser's pointer modes: Work (default) sends absolute positions, Game captures the mouse on a click (Android pointer capture, the click is not sent) and sends relative motion; the choice also sets the host's stream mode. With keyboard capture on (default), Esc and Win combinations go to the PC and holding Esc for 1 s releases a captured mouse; Android itself keeps Win alone, Alt+Tab and Print Screen. A `dataSync` foreground service started with the session keeps it, its transfers and reconnects alive in the background, with a notification that has a Disconnect action; without it (refused, Android's time limit, or the setting off) the session stops 30 s after the app leaves the foreground.

Copy from the PC automatically defaults on in Android Settings. Host clipboard text is written only while the activity is resumed and focused. The latest background snapshot waits for focus to return; automatic copying applies it when enabled. With automatic copying off, it remains pending for the Copy PC clipboard row in More. That row is enabled only while a snapshot is pending and describes its text length. Tapping it copies the snapshot to the phone clipboard and clears pending; local clipboard changes or paste also discard pending content. The Android host clipboard channel currently supports text only.

The Android signaling callback rejects binary packets with unsupported types or lengths before copying them. Cursor position and appearance updates share one pending delivery that retains the latest value of each.

Each accepted Android signaling hello replaces the media leg, including when its old socket is already gone. Every media leg sends stream start and a fresh first-frame handshake; a frame presented before signaling admission is remembered for that leg and completes the handshake when matching admission arrives. Attached decoder surfaces have their own generation: missing output triggers a forced keyframe retry after two seconds, then one media restart after a second miss; stale surface output cannot satisfy the watchdog. Exhaustion cancels pending recovery timers and blocks further automatic media restarts, with an error state offering Retry. Only a new attached surface or user retry resets that limit.

Android reconciles cursor echoes using wrap-safe movement acknowledgements, so delayed feedback cannot overwrite newer local touch prediction. Wheel-only input does not create pending cursor authority or block external cursor movement. Mouse wheel and touchpad scroll (`ACTION_SCROLL`) are routed by `StreamActivity` from the generic-motion listener while the pointer is uncaptured and from the captured-pointer listener after capture; a sample reaches one of them only. Motion admission uses a 512-byte signaling queue budget and keeps coalesced movement pending under congestion. Captured-mouse buttons remain behind their preceding movement, and later reliable input preserves that order. The host coalesces queued motion between input barriers and acknowledges accepted sequenced motion even when its net displacement is zero. Routine cursor feedback retains the latest position and highest wrap-safe acknowledgement, including when a newer snapshot has no acknowledgement of its own.

The Android IME uses a bounded local Editable with real committed text, selection and composing spans. It reconciles the changed suffix once per outer edit batch using code-point Backspaces and Unicode text, and advances its remote snapshot only when the edit is accepted. Deletion beyond retained context replaces the full known segment plus the outside deletion span, then re-sends the resulting local text. IME key events flush pending edits before sending the key, even inside a batch. Soft-keyboard Enter down/up, editor actions and committed newlines send text before one Enter tap or key pair. Enter, Tab and navigation retire local context after key-up or a completed tap; their input restart is posted after the IME callback, and a later edit cancels stale restart work. Hardware and QuickBar keys retain their immediate reset behavior. Android 14 `replaceText` uses the same edit and reconciliation path. Remote clicks, navigation, Enter, clipboard paste, desktop changes, signaling loss and keyboard hide reset the known text context. Local selection away from the end is a reset point; remote editing keeps the caret-at-end contract. Autocorrect and suggestions remain enabled. IME Backspace and Delete key repeats remove the preceding grapheme from the known end-caret segment without clearing word or composing context; each removed Unicode code point produces one host Backspace (one for a supplementary emoji, two for a base letter plus combining accent). Once that segment is empty, each Backspace/Delete repeat sends a complete host key tap, and its key-up is consumed. Optional `BubblePlayIme` DEBUG logging records only method, lengths, counts, key and selection/composition metadata; enable it with `adb shell setprop log.tag.BubblePlayIme DEBUG`.

Android shows Follow active window in the switch-screen popover when the host advertises `followWindow`, with the same control message and `monitor-list.follow` state as the browser. File uploads use the save/paste route rather than desktop OLE drops. See the [Android guide](../../android/README.md) for layout, settings, signing, tests and device-validation limits.

## Windows

The native Windows client ([windows-client.md](windows-client.md), code in `client-win/src/ui/session.rs`) draws its chrome in egui over the video, attached to the top edge. Every piece floats over the video; nothing shrinks the picture.

- A small collapsed tab sits at the top edge. Opening it shows the toolbar strip: display, Work/Game mode (one button showing the current mode; a click switches to the other), quality, audio, stats and leave. Below 1000 px of window width the strip goes compact (no release chord in the capture group, quality as an icon only).
- The display button opens the picker ("Show display"): a map of the host's monitors and one row per monitor, with the current one marked. Keys 1-9 pick a display and Esc closes the picker. A pick sends the browser's `monitor` request. Until the host answers, the rows are disabled and a notice says the display is switching. If the host refuses, an error notice shows its reason. The Follow row is not drawn.
- Mode changes are sent live, as the browser sends them.
- Quality and audio controls are drawn disabled on a live session (same place and size, with a "not available yet" tooltip) until the client can send those changes.
- Other pieces: the stats panel, the capture/released toasts, a reconnecting card over a dimmed video, the Admin-required banner and the secure-desktop badge.

## Input sequencing and scroll

Browser `InputController` and Android `RemoteInput` allocate absolute-v2, motion-v2 and buttons-at packets from one shared wrapping u16 counter. Each successfully sent pointer or wheel packet consumes its own sequence. Absolute position and wheel distance remain independent, including when both arrive in the same frame; an absolute packet is followed by motion-v2 carrying the wheel. Large wheel distances split across i16 packets, and refused tails remain pending for retry. Browser two-finger horizontal scrolling negates finger X, matching Android.

The warm host starts a fresh input sequence space when a detached viewer attaches or an authenticated WSS start replaces its media epoch. This resets the local sink, coalescer and retained cursor acknowledgement together. Ordinary release-all, monitor changes and repeated starts for the same epoch retain the stale gate. The privileged path rotates the existing Agent lease identity and replaces its interactive input proxy using existing IPC messages; input stays behind its verified-frame and presentation gates. Queued cursor feedback cannot import an old acknowledgement while that gate is closed. No packet fields or types change.

The pointer watermark rejects duplicate/reordered motion and preserves reliable click/drag barriers. Wheel distance has separate replay tracking: an unseen wheel within the unambiguous u16 half-range is injected even if its pointer displacement is stale, without rewinding the cursor. Wheel-bearing packets keep their original sequence identities through host coalescing, so repeated delivery cannot scroll twice. Events at least 32768 sequence steps behind the watermark cannot safely be distinguished from sequence reuse and are rejected through the existing stale-sequence diagnostics. The lossy motion transport cannot recover packets that never arrive.
